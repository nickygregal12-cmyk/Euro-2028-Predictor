# League season development seed

**Dated evidence. 5 August 2026.** Records one application of the development
seed and the state it produced. A snapshot; it must keep saying what was true
when it was written.

## What was empty

`Premier League 2026/27` and `Scottish Premiership 2026/27` have existed as
`tournaments` rows since the C1b catalogue migration. On development both were
**completely empty** — zero teams, zero matchweeks, zero fixtures.

That is worth stating plainly because of what it implied. Every season authority
the repository has built reads from those tables: the Match Predictor card and
its locks, matchweek scoring, standings, Last Man Standing eligibility and
round resolution, the Championship round calendar and its launch driver. With
the tables empty, all of it was unreachable code. Nothing could be entered,
locked, scored, settled or displayed, and no surface built on top of it could
have been reviewed.

## The calendar is invented, and that is not a caveat in small print

These are **not** the real 2026/27 fixture lists and the clubs are **not** the
real league members. They cannot be: a real fixture list is exactly what a
provider feed supplies, and which clubs contest a 2026/27 season is decided by a
2025/26 campaign this repository has no source for.

The club names are therefore invented outright — in the spirit of the Euro
seed's `Team A1`…`Team F4` placeholders, but shaped like club names so a screen
full of them looks like the product. They are readable enough to review a
surface against and impossible to mistake for a real league table.

**This is not a substitute for the provider work.** It is what makes the season
authorities runnable and the surfaces reviewable while the provider question is
still open.

## Verified on development, not merely applied

Four properties, each checked against the database after the write:

| Property | Result |
| --- | --- |
| Every pair meets exactly twice | 0 exceptions |
| Every pair plays once at each ground | 0 exceptions |
| Every club plays exactly once per matchweek | 0 exceptions |
| No club plays itself | 0 |

The third is also enforced by `assert_season_fixture_shape`, so a generator that
got it wrong would have been refused. The other three are the quiet ones: a
schedule where some pair never meets, or meets twice at the same ground, inserts
perfectly happily and is only noticed — if ever — by a table that stops adding
up in March.

Kickoffs are stored from `Europe/London` wall-clock times rather than fixed UTC
offsets, so the August-to-May crossing of BST into GMT is correct. August 12:30
London resolves to 11:30Z and December 15:00 London to 15:00Z, both confirmed.
This is not cosmetic: matchweek locks derive from the earliest kickoff, so an
hour of drift moves when somebody's card shuts.

## The authorities it unblocked

Read-only checks after seeding:

- `season_matchweek_lock_at` resolves for every matchweek in both seasons, with
  the Last Man Standing 30-minute buffer visibly ahead of Match Predictor.
- `next_eligible_league_round` returns a round for both seasons.
- `select_season_cup_format` for a twelve-entrant field returns **different
  shapes for the two seasons**, which is the useful part:

| Season | Future matchweeks | Format for 12 entrants |
| --- | --- | --- |
| Premier League | 38 | `single_group` — 3 meetings, 33 rounds, then a 5-round split into two halves of 6 |
| Scottish Premiership | 21 | `groups` — two groups of 6 |

That is not a tuned result but it is a fortunate one. Contract 111 launches
`single_group` and refuses `groups` **by name**, so development now carries one
season exercising each path against real rows rather than test fixtures.

The Scottish Premiership shows 21 future matchweeks rather than 22 because its
matchweek 1 (1 August) is already in the past relative to the seeding date, and
that single past matchweek is what tips it from `single_group` to `groups`. It
is left that way deliberately. Moving the season start a week later would make
both seasons launchable and lose the refusal path.

One consequence to know about: Scottish matchweek 1 is locked with no
predictions and no result, so it is inert. If a clean all-future calendar is
wanted instead, change `firstSaturday` for that season in the generator, clear
its fixtures and re-run.

## Re-running

The seed is idempotent and additive. A season that already has fixtures is left
untouched with a notice, and **no path through it deletes a row** — so re-running
cannot double a calendar and cannot destroy one. Re-seeding a season therefore
means clearing it first, deliberately.

```bash
node --experimental-strip-types scripts/seed-dev/seed-league-seasons.ts
```

It only prints SQL; it opens no connection, so running it is never itself the
act of changing a database.

The schedule is generated in SQL, and the TypeScript circle method in the same
file is the oracle it was checked against — the two were compared row for row
for both a 12 and a 20 club season and agreed on all 512 fixtures.
`tests/dev/seedLeagueSeasons.test.ts` holds the oracle with property assertions,
and three mutants (dropped home/away alternation, an unreversed second half, and
a rotation that seats a club out) were each confirmed to fail it.
