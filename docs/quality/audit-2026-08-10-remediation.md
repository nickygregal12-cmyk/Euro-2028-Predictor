## How the register is annotated

The `ID`, `Item`, `Area`, `Who` and `Notes` columns are copied **verbatim** from the audit
remediation prompt pack. Where the pack contradicts a repository authority, the contradiction is
recorded in `Notes` as a trailing **`AUTHORITY CHECK`** clause, dated, with the authority that wins.
The audit's original wording is left standing in front of it and is not edited. **Nothing has been
silently reconciled**, and no item's substance has been changed on the strength of one of these
checks — a session taking the item still verifies it against code itself.

`Status` starts at `TODO` for every row except **AUD-06**, which the register itself instructs to
initialise `ALREADY DONE` and which is verified merged on `main`. That single deviation from
"initialise `TODO` for every row" is deliberate and flagged in Handover.

audit did not have that measurement; the repository does, and the authority wins.

**INP cannot be asserted in a lab run.** Interaction to Next Paint is a *field*
metric — it requires real user interactions, and Lighthouse's own lab run reports
Total Blocking Time as its proxy. An assertion named `interaction-to-next-paint`
in `lighthouserc.json` would never fire. TBT is assertable and LCP and CLS are
assertable; INP belongs to AUD-19's RUM work, where `web-vitals` reports it from
real sessions.

**What was deliberately not added:** numeric LCP/CLS/TBT floors. The same baseline
says a floor set before anyone has measured run-to-run drift on shared CI
infrastructure is a false-alarm generator, and the step is report-only precisely
so that drift can be observed first. The accessibility assertion already in the
config is `error` at `minScore: 1`, so the gate arrives with teeth when it is
promoted.
