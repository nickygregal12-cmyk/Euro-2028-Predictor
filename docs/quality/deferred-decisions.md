## Register rules

- Use this register only for conscious postponement, not as a general backlog.
- Every item must have a decision owner and concrete review trigger.
- Completed, rejected, resolved and superseded decisions remain for traceability.
- Tagged-source behaviour and hosted deployment are separate evidence states.
- Where a resolved decision leaves a separate security concern, retain that concern in the risk register.
- Product sequencing remains in the roadmap; implementation work remains in GitHub Issues.
