# Tooling assurance activation

## Problem

The repository has broad developer, test and security tooling, but several
controls are generated without consumption evidence, report findings without a
regression gate, or cover the TypeScript application more strongly than the
Python AI Lab. A configured tool must not be mistaken for an executing or
enforced control.

## Operator outcome

A maintainer or coding agent can determine which controls ran, which optional
tools were used, and whether a change introduced new architecture, dependency,
documentation, accessibility, security or reproducibility debt. Critical merge
evidence fails closed; optional diagnostics stay explicitly optional.

## In scope

- Repair documentation checks that can accept contradictory current hosted
  migration claims.
- Give agents one supported Graphify command that verifies snapshot freshness
  and runs a bounded query/path/explain operation.
- Record Graphify/navigation use for broad pull requests without making an
  optional graph a product authority or universal merge gate.
- Make Python AI Lab dependency resolution reproducible and add focused lint,
  vulnerability, coverage and property-test controls.
- Prevent new dead-code/dependency debt while retiring the measured baseline.
- Extend existing CodeQL, workflow hardening, accessibility, performance,
  production smoke and dependency-update mechanisms before adding overlapping
  platforms.
- Remove redundant or genuinely unused tooling where replacement evidence is
  already present.

## Out of scope

- Product, scoring, lock, reveal, settlement, membership or competition-rule
  changes.
- Supabase migrations, hosted database mutation, provider calls or Production
  deployment/configuration.
- Enabling optional model-backed Graphify, OmniRoute, Agent Mail, Beads,
  semantic merge drivers, React Scan or Lost Pixel as background services.
- Installing conditional tools that lack their prerequisite, including API
  schema fuzzing without a stable owned schema or an SBOM without a consumer.
- Replacing Vitest, Playwright, CodeQL, Betterleaks, Oxlint, Stylelint, k6,
  Supabase migrations or Playwright visual baselines with competing systems.

## Acceptance scenarios

1. A hosted-state document that says the current table is level while adjacent
   current-state prose says older contracts are unapplied fails a deterministic
   test.
2. A Graphify-capable agent can obtain the merged snapshot, prove the source SHA
   it represents, and run `query`, `path` or `explain` through one repository
   command; an unavailable or stale graph is reported honestly and never
   treated as authority.
3. A pull request that changes broad/cross-layer code has an explicit place to
   state which navigation method was used or why Graphify was unnecessary.
4. AI Lab CI installs exactly the committed dependency resolution and refuses a
   stale lock.
5. Python lint, known-vulnerability scanning, CodeQL analysis and coverage run
   in CI without weakening the existing TypeScript gates.
6. New undeclared dependencies, unused dependencies/files or exported-dead-code
   growth fail against a committed baseline while existing classified debt can
   be retired incrementally.
7. Storybook component worlds receive automated accessibility checks; critical
   browser smoke can exercise non-Chromium engines without tripling the full
   suite.
8. Production source maps are uploaded only in an explicitly configured trusted
   build and the app still builds without Sentry upload credentials.
9. Link checking, dependency updates, production smoke and workflow hardening
   run on controlled schedules with pinned dependencies and bounded permissions.
10. Architecture analysis still covers a non-zero module graph and the relevant
    verification command is part of an always-present CI result suitable for a
    required branch rule.

## Security and privacy constraints

- No secret may be committed or printed by a new check.
- Sentry upload credentials are build-only and optional; public source-map
  serving is not introduced.
- Browser, Graphify and production-smoke tools must not consume paid football or
  odds provider quota.
- Automated security scans use local or explicitly authorised preview targets;
  no active attack is run against Production.
- Developer tooling remains outside application runtime dependencies unless its
  product-runtime purpose is explicit.

## Effects

- **Database migrations:** none.
- **Hosted database state:** none.
- **Production mutation/deployment:** none.
- **Paid provider calls:** none.

## Completion predicate

All unconditional additions and extensions in the audit are either implemented
with executable evidence or explicitly deferred because an open branch or an
external repository setting is the remaining prerequisite. Conditional and
conflicting candidates remain uninstalled. The work is split into reviewable
commits/PRs, and each handoff names exact tests, unresolved external settings
and deliberate non-actions.
